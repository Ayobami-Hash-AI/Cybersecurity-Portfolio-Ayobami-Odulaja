# Portfolio Publishing and Security Standards

This public repository is a professional learning portfolio. Project claims must be supported by source code, lab output, or other appropriately documented evidence.

## Before publishing

- Remove passwords, API keys, tokens, session identifiers, personal contact details not intended for publication, and private hostnames/IP addresses.
- Sanitize screenshots and logs, including usernames and identifiers where necessary.
- Verify that educational content can be shared under the platform's rules; do not publish restricted challenge solutions, flags, or proprietary course materials.
- Distinguish completed work, work in progress, and planned work.
- Do not describe guided labs as production deployments.
- Preserve relevant evidence and clearly state investigative limitations.
- Prefer readable Markdown summaries with links to source files and sanitized artifacts.
- Check filenames, internal links, and code examples before committing.

## Project write-up template

1. Objective and scope
2. Environment and tools
3. Methodology and steps performed
4. Commands/configuration and observed results
5. Evidence and screenshots
6. Findings, limitations, and troubleshooting
7. Security relevance and lessons learned
8. Next improvements

## Reporting security concerns

Please do not publish sensitive findings, secrets, or private information in a public issue. Use GitHub's private vulnerability reporting feature if enabled, or contact the repository owner privately.
